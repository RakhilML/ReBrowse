Learn an API from its traffic

Your frontend already documents its API.

Every call it makes is in the browser's network panel. rebrowse reads that traffic and finds the API behind it. Then it writes docs, runs a mock, keeps a safe baseline and checks every pull request against it.

RULE 1

No secret leaves. rebrowse removes cookies, tokens and passwords as it reads.

RULE 2

Nothing changes data without you. rebrowse sends reads only, unless you confirm a write.

Three jobs, one committed file

The frontend owns the baseline. Both repos check their pull requests against it.

main frontend repo

e2e tests

Write one HAR file for each test into test-results/.

rebrowse baseline test-results/

Write api-baseline.json. Commit it. Never commit the HAR files.

rebrowse openapi api-baseline.json

Refresh docs/openapi.json. Same bytes when the API is the same.

Pull request frontend repo

e2e tests

Record the new run.

rebrowse diff api-baseline.json test-results/

Fail on a change that breaks the frontend.

rebrowse coverage test-results/ --fail-under 80

Fail when tests miss too many API calls the code can make.
